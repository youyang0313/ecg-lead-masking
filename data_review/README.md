# PTB-XL data review

Updated 2026-10-23. This supports the report's problem definition and input feasibility checks. It is not a model implementation or classification result.

Only five public metadata/documentation files from **PTB-XL 1.0.3** are archived under `metadata/`. [Source URLs and SHA-256](D:/AAAurora/NTUDL/ECGProject/data_review/sources.json) preserve provenance. The larger CSV was obtained from PhysioNet's public S3 bucket, listed by its [official project page](https://physionet.org/content/ptb-xl/1.0.3/); the main website transferred it slowly. Original downloaded bytes are retained. The official Python example was read as text and **not executed**.

The [metadata audit result](D:/AAAurora/NTUDL/ECGProject/data_review/metadata_audit.json) verifies codebook categories, development-label support and patient-separated folds. Fold 10 contributes identifier/fold counts only; its `scp_codes` dictionary is not parsed. No prediction scores or test annotation support counts are present in this review.

A subsequent [training-only waveform pilot](D:/AAAurora/NTUDL/ECGProject/data_review/waveform_pilot/README.md) archives 100 records from 100 training patients (200 original `.hea`/`.dat` files), their source hashes, reproducible checks and two input illustrations. All 100 records passed the specified checks and later matched standard WFDB 4.1.2 reading exactly. This purposive sample does not establish full-cohort signal quality, and its normalization statistics are for illustration only. The pilot itself used no validation/test waveforms and trained no model.

The [full development preprocessing](D:/AAAurora/NTUDL/ECGProject/data/ptbxl_1_0_3/README.md) is now complete: 17,084 training records and 2,146 validation records passed structural checks, with no additional waveform exclusions. Training-only per-lead normalization parameters and aligned arrays are saved. [Findings and limitations](D:/AAAurora/NTUDL/ECGProject/data_review/PREPROCESSING_REVIEW_ZH.md), the [audit](D:/AAAurora/NTUDL/ECGProject/data_review/preprocessing_audit.json) and [verification](D:/AAAurora/NTUDL/ECGProject/data_review/preprocessing_verification.json) preserve the results. No model was trained during preprocessing. Subsequent [model implementation and engineering runs](D:/AAAurora/NTUDL/ECGProject/training/ENGINEERING_REVIEW_ZH.md) and [six full-budget models](D:/AAAurora/NTUDL/ECGProject/training/MAIN_TRAINING_REVIEW_ZH.md) are archived separately; test waveforms and test diagnostic annotations remain unused.

The corresponding [v2 study scope](D:/AAAurora/NTUDL/ECGProject/report/STUDY_SCOPE_V2.md) explains the implications: five diagnostic superclasses form a multi-label task; AFIB is a rhythm statement; NORM is not the complement of other labels; zero-likelihood statement entries are not discarded simply because their numeric value is zero; and records lacking diagnostic mappings must not become all-negative examples.

`audit_metadata.py` reproduces the metadata-only check using the Python standard library. `fetch_metadata.py` retrieves only an explicit allowlist of metadata/documentation. Neither script trains a model or loads ECG signals. The separate pilot uses `prepare_waveform_pilot.py`, `check_waveform_pilot.py` and `plot_waveform_pilot.py`; development preprocessing uses `prepare_development.py` and `preprocess_development.py`. Test-cohort processing remains pending; any additional exclusion rules would need separate justification and fresh cohort counts.
